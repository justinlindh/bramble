# Parser fuzzing

libFuzzer harnesses over the code that parses attacker-controlled LoRa frames
before any AEAD tag or HMAC is verified.

| Target | Under test | Harness |
| --- | --- | --- |
| `fuzz_packet` | every `bramble_*_deserialize` in `components/packet/packet.c`, plus the matching serializers on a round trip, `bramble_header_build_aad`, and `bramble_build_aead_aad` | `fuzz_packet.c` |
| `fuzz_fragment` | `reassembly_add` / `reassembly_collect` / `reassembly_purge` / `reassembly_get_first_packet_id` and `fragment_split` in `components/fragment/fragment.c` | `fuzz_fragment.c` |

Both build with `-fsanitize=fuzzer,address,undefined` and
`-fno-sanitize-recover=undefined`, so any undefined behavior aborts rather
than being logged and stepped over.

## Running

```bash
bash test/fuzz/run_fuzz.sh                  # the CI budget: 30s per target
FUZZ_SECONDS=600 bash test/fuzz/run_fuzz.sh # a longer local campaign
bash test/fuzz/run_fuzz.sh --regen-corpus   # rebuild the committed seeds
```

Requires `clang` with the libFuzzer and sanitizer runtimes. The script probes
for both and fails with an explanatory message when either is missing; it never
skips, because a skip would turn the CI gate into an advisory check (see
`docs/quality-policy.md`).

## Reproducing a finding

A crash, timeout, or OOM writes the offending input to `test/fuzz/artifacts/`
and fails the run. CI uploads that directory as a job artifact. Replay it
against the target directly:

```bash
test/fuzz/build/fuzz_packet test/fuzz/artifacts/crash-<hash>
```

## Corpus

`corpus/packet/` and `corpus/fragment/` are committed and generated by
`gen_corpus.c` from the same wire frames the host suites `test_packet.c` and
`test_fragment.c` assert on. Seeding from valid frames is what makes a
30-second budget meaningful: the mutator starts on real field boundaries
instead of spending the whole run rediscovering that a beacon is 54 bytes long.
Regenerate the corpus with `--regen-corpus` whenever a wire format changes, then
review and commit the diff.

## Input encodings

`fuzz_packet` reads byte 0 as a parser selector and hands the remaining bytes to
that parser as a frame. `fuzz_fragment` reads a sequence of 7-byte commands
(`op`, `frag_index`, `frag_total`, `message_id` low, `message_id` high, payload
length, clock advance), each optionally followed by payload bytes, and replays
them against one reassembly context. Both harnesses copy every frame or payload
into a heap allocation sized exactly to its length, so a one-byte over-read
lands in an ASan redzone instead of being absorbed by an oversized stack buffer.

## Scope note

ASan finds spatial and temporal memory errors. It does not find reads of
uninitialized memory, which is a real defect class in these parsers: see
issue #77 problem 1, where a beacon `name_len` that exceeds the frame is left at
the attacker's value with `name[]` unwritten. An MSan build of `fuzz_packet`
also stays quiet on it today, because the uninitialized bytes are `memcpy`ed
onward rather than branched on. Catching that class needs either the defect
fixed or a harness assertion that consumes the affected field, and both belong
with the fix rather than here.
